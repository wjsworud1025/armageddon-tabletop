첨탑은 기존 고각 카메라가 발을 위로 잘라냈다. 저각·중각 사진 20장으로 외곽을 복원하고 고각 사진 10장의 외곽과 맞춰 세 번째 촬영 높이의 투영을 다시 구했다. 세 높이 모두에서 미사용 사진을 특징점 매칭, 초기 카메라 축척 추정, 윤곽 결합 및 표면 채색에서 제외했다. 사진마다 닫힌 흰 구멍에만 두 픽셀의 여유를 주어 다리와 배선 사이를 열었다.

첨탑의 게임 치수는 가로 3.50, 깊이 1.50, 높이 2.98인치다. 가로는 카탈로그 추정값을 입력했고 깊이와 높이는 복원 결과에서 계산했다. 실물 자 측정값은 없다. 여섯 사진에서 보이는 가로·세로 길이와 렌더의 편차는 최대 1.3%였다. 480픽셀 비교 영상에서 면적 12픽셀 이상인 닫힌 흰 구멍의 배경 보존율은 다섯 사진에서 79.5–92.2%였다. 고각 03-11에서는 작은 구멍 두 곳의 총 24픽셀 중 4픽셀만 남았다. 기물 두 점은 동일 사출 조형의 메시와 도색을 공유한다. 로컬 메시 하나는 정점 24,271개, 삼각형 50,616개, 522,152바이트다.

재현에는 NumPy, Pillow, OpenCV와 SciPy가 필요하다. 아래에서 `PHOTOS`는 첨탑 회전 사진 36장이 있는 로컬 폴더다. 첫 명령은 여섯 장을 초기 보정부터 제외한다. 두 번째 명령은 30장으로 검증하고, 검증 후 36장으로 출력 파일을 만든다. `--audit-profile`은 480픽셀에서 면적 12픽셀 미만의 독립 화소 덩어리를 거른 뒤 투영 가로·세로 비율과 닫힌 구멍의 배경 보존율도 구한다.

```sh
python reconstruction/calibrate.py PHOTOS lens.json --footprint --align-high --holdout 01-03 02-07 03-11 01-08 02-12 03-04
python reconstruction/reconstruct.py PHOTOS --footprint --width 3.5 --inches 3.5 --density 63 --allow 0 --extent 1.3 --image-size 680 --apertures 2 --audit-profile --holdout 01-03 02-07 03-11 01-08 02-12 03-04 --lens lens.json --comparison held-out.png --output pylon.whm
python reconstruction/test_terrain_calibration.py
```

## 생성과 확인

1. 한 그룹의 원본을 `01-01.webp`부터 `03-12.webp`까지 담은 폴더를 준비한다. Pillow는 파일 헤더를 읽으므로 실제 JPEG 이미지도 지원한다. 가로형 사진에는 정사각형 흰 여백을 더해 아틀라스와 같은 투영 좌표를 사용한다.
2. `reconstruct.py`는 NumPy와 Pillow로 받침대 투영을 맞추고 사진의 윤곽을 공간에 역투영한다. 윤곽이 만나는 부피에서 표면을 추출하고 각 정점의 가시성과 표면 방향을 고려해 사진의 색을 합친다. 둥근 베이스는 제품 지름, 차량의 타원 베이스는 장축, 지형은 카탈로그의 추정 너비를 기준으로 스케일을 정한다.
3. 선택적으로 `calibrate.py PHOTOS lens.json`을 실행하면 OpenCV의 SIFT와 SciPy를 사용해 반복되는 특징점에서 카메라를 보정한다. 예시로 캡틴에는 유효한 특징점 대응 1,831쌍을 사용했다. 게임에는 이 Python 의존성이 필요하지 않다.
4. 저장소 루트에서 캡틴을 다시 생성하는 명령은 `python reconstruction/reconstruct.py PHOTOS --inches 1.57480315 --density 51 --allow 1 --image-size 560 --lens lens.json --output captain.whm --comparison held-out.png`이다. 모델별 JSON에는 저장된 카메라 투영과 지면 중심이 들어 있다.
5. 로컬 복원 파일과 촬영 자료를 설치한 Windows에서 `node reconstruction/preview.mjs vanguard-4 comparison.png`를 실행하면 실제 WebGL 셰이더로 네 방향을 렌더링한다. 게임은 카메라와 각도가 가까운 사진을 3D 표면에 투영한다. 사진이 없는 위·아래 방향은 융합된 표면색을 쓴다.
